Working thesis

An optional decision service could handle repeated, bounded judgments around agent runs. The strongest branches to investigate are context selection, skill selection, and dispatch classification.

Price is unlikely to decide the winner. At the listed rates, 1,000 requests of 10,000 input tokens would cost about $0.50 for Snap or $0.42 for Jev. Accuracy and avoided agent work matter more than that eight-cent difference.

BusterClaw's economics are different. Agent harnesses currently run under the operator's own subscriptions. A separate decision API adds a bill; any improvement in latency, token use, or subscription capacity still needs measurement.

03 / Connection points

Five places to investigate.

Each branch starts with a decision BusterClaw might benefit from. The fit assessments below are research hypotheses. Expand a row for the proposed role and the evidence we would need.

AContext & memory selectionHelp the agent find the evidence that matters.Priority research
Example decision“Which of these prior run summaries would help answer this request?”

Existing connection: Memory.search/2 retrieves run summaries using SQLite FTS5 and BM25 ranking. A decision model could rerank the shortlist before it reaches an agent.

Candidate fit: Both. Jev has a published reranking example; Snap permits a much larger candidate context. Neither automatically discovers files we have not supplied.

Question to resolve: Does reranking recover useful evidence without dropping necessary details, and does it save more agent effort than the extra call costs?

BSkill selectionChoose a relevant capability, including “none.”Priority research
Example decision“Which available skill best matches this task, or does no skill apply?”

Existing connection: BusterClaw's Skills context and the skill information exposed to agents. A selector could return an existing skill identifier for the agent to consider.

Candidate fit: Both. TypeSafe's skill-selection cookbook ranks and checks candidates from a 182-skill Hermes catalog. That demonstrates a pattern, not compatibility or measured improvement with BusterClaw.

Question to resolve: Which catalog and descriptions does BusterClaw actually control, and does the suggestion improve the agent's choice? Selecting a skill would not install or execute it.

CDispatch classificationIdentify the kind of work and appropriate route.Priority research
Example decision“Is this a research request, a scheduling request, or an item needing clarification?”

Existing connection: The durable Dispatch queue and Dispatcher. Semantic classification could help choose among explicitly supported workflows.

Candidate fit: Both. Compact requests are a plausible Jev baseline; Snap may help when classification depends on a long thread or document.

Question to resolve: Can either improve routing beyond the existing rules without starving, misrouting, or silently discarding work? Caller trust, kill switches, and budget limits remain code decisions.

DBrowser-state checksCompare an observed page with an expected state.Explore later
Example decision“Does this page show a completed submission, a validation error, or an unresolved state?”

Existing connection: Browser Agent Mode and observed browser results. A model could classify supplied evidence after an action.

Candidate fit: Snap can accept screenshots alongside text. Jev would require extracted page text or structured state.

Question to resolve: Are visual judgments reliable on actual BusterClaw pages? The classifier would provide evidence for review; it would not authorize a payment or substitute for an action receipt.

EResult & completion reviewFlag a mismatch between the task and its evidence.Explore later
Example decision“Does the supplied result address the requested outcome, or should the agent inspect it again?”

Existing connection: Agent results, dispatch completion, and recorded run summaries. A checker could flag missing evidence or unresolved requirements.

Candidate fit: Both, for a carefully scoped rubric. Longer history or screenshots may favor investigating Snap.

Question to resolve: How often does a checker approve incomplete work or reject valid work? Test exit codes, acknowledgments, and other exact checks should remain authoritative where available.

Vendor evaluation / Snap

A reported benchmark lead.

Subquadratic reports 61.7 for Snap versus 57.9 for Jev on Decision Index 0.2.1. It also reports a decision in about one second with 100K tokens. These results do not establish accuracy or end-to-end speed in BusterClaw, and that benchmark version is a dated snapshot.

External research / Jev

Strength varies by task.

An October 8 preprint finds Jev competitive on knowledge and commonsense benchmarks, with a pronounced weakness on mathematical word problems. This supports investigating bounded semantic decisions; it does not validate agent routing or completion checks.

Read the benchmark preprint ↗
Documented limitation / Jev

Confidence needs interpretation.

Jev's confidence is computed from its answer distribution. It is not a measured probability that a BusterClaw action will succeed. TypeSafe also documents sensitivity to irrelevant context, option order, and adversarial content.

Confidence semantics ↗ · Known limitations ↗
Data handling / Both

Private context crosses a boundary.

SubQ documents indefinite retention by default and organization-level zero retention on request. TypeSafe states that it does not train on customer requests and offers enterprise zero retention. Jev's default retention needs further review before any private-data experiment.

SubQ retention ↗ · TypeSafe policies ↗

BusterClaw owns authority.

Permissions, trust tiers, credential access, budget enforcement, and exact calculations remain in BusterClaw's deterministic code. A decision model can recommend a route or flag evidence. Its answer does not grant access or override an operator choice.

05 / Research frontier

What would change our mind?

These questions define the next research pass. They are not an implementation commitment or an instruction to send workspace data to either service.

  1. Where is there repeated judgment worth offloading?

    Identify real decisions currently consuming agent turns. Separate those from checks that ordinary code already handles cheaply and exactly.

  2. Which model makes fewer costly mistakes?

    Compare both on the same labeled tasks, including ambiguous requests and “none of the above.” Inspect false positives, missed evidence, and confidence behavior by task.

  3. Does the complete workflow get better?

    Measure added latency, agent turns avoided, input volume, retries, and task completion. Compare against today's behavior and a simple rules-based baseline.

  4. How much context is actually necessary?

    Compare concise retrieved context with larger inputs. A larger context limit is useful only if it changes the quality of the decision.

  5. What are the operational terms?

    Confirm account access, rate limits, data retention, model versioning, and outage behavior. Define a fallback to the existing path for uncertainty or service failure.
